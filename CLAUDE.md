# El Toro Battalion — Project Guide

## What This Is

Static website for El Toro Battalion, U.S. Naval Sea Cadet Corps (USNSCC), based in Irvine, CA.
Migrated from WordPress to a Jinja2 static build system. Deployed on Netlify.

- **Production**: https://eltorobattalion.org
- **Netlify site**: golden-pastelito-223a0c.netlify.app
- **GitHub**: https://github.com/cvbiju/eltoro-website

---

## Directory Layout

```
templates/          ← SOURCE — always edit here
  _base.html        ← shared layout: nav, head, footer, scripts
  pages/            ← 13 page templates
    index.html, about-us.html, calendar.html, cadet-mess.html,
    enrollment.html, gallery.html, general-knowledge.html,
    grooming-uniform.html, meet-the-officers.html, parents.html,
    physical-fitness.html, programs.html, 404.html

public/             ← BUILD OUTPUT — never edit directly
  *.html            ← generated by build.py (overwritten every build)
  assets/           ← images, PDFs, videos (source files, not generated)
  admin/            ← Netlify CMS (static, not generated)
  robots.txt, CNAME

build.py            ← Jinja2 build script (renders templates → public/)
netlify.toml        ← build config, security headers, CSP, redirects
requirements.txt    ← Jinja2 dependency
scripts/            ← utility/migration scripts (see scripts/README.md)
tests/              ← visual regression screenshot scripts
```

---

## The #1 Rule

**Never edit `public/*.html` directly.** Every build overwrites them.
All content changes belong in `templates/pages/`. Nav/footer/head changes go in `templates/_base.html`.

---

## Build & Run

```bash
pip3 install -r requirements.txt    # one-time setup (use pip3, not pip — macOS PATH)
python3 build.py                    # generates all pages in public/
python3 scripts/serve_local.py      # local dev server on :8000
```

GitHub Pages deploys the `public/` directory automatically on every push to `main`.

## Template Blocks

Every `templates/pages/*.html` uses `{% extends "_base.html" %}` and overrides blocks:

| Block | Default | Purpose |
|---|---|---|
| `page_title` | `El Toro Battalion` | `<title>` tag |
| `html_attrs` | _(empty)_ | Attributes on `<html>` (e.g. `class="scroll-smooth"`) |
| `head_extra` | _(empty)_ | Page-specific `<style>` or `<link>` in `<head>` |
| `body_class` | _(empty)_ | CSS classes on `<body>` |
| `main_attrs` | `class="flex-grow"` | Attributes on `<main>` |
| `content` | _(required)_ | Main page content |
| `body_extra` | _(empty)_ | Between `</main>` and `<footer>` (lightbox modals, etc.) |
| `scripts` | _(empty)_ | Page-specific `<script>` before `</body>` |
| `netlify_identity` | _(empty)_ | Netlify Identity widget (CMS pages only) |

**Jinja2 gotcha**: JavaScript template literals (`${variable}`) must be wrapped in
`{% raw %}...{% endraw %}` to prevent Jinja2 from parsing them as its own syntax.
See `templates/pages/gallery.html` for a working example.

## Adding a New Page

1. Create `templates/pages/{slug}.html` extending `_base.html`
2. Add nav links in `templates/_base.html` (desktop dropdown + mobile menu)
3. Add the slug to `public/robots.txt` if search engines should not index it
4. Run `python3 build.py`
5. If the page fetches any new external domain, add it to the CSP in `netlify.toml`

Use `/project:new-page` for a guided scaffold.

## Third-Party Services

| Service | Purpose | Config location |
|---|---|---|
| Web3Forms | Enrollment form submissions | `<input name="apikey">` in `templates/pages/enrollment.html` |
| Google Drive API | Gallery image loading | Key + folder ID hardcoded in `templates/pages/gallery.html` |
| Google Calendar | Calendar page embed | Embed URL in `templates/pages/calendar.html` |
| Netlify CMS | Content editing UI | `public/admin/config.yml` |
| Netlify Identity | CMS auth | Widget in `_base.html` `netlify_identity` block |

**API keys are hardcoded in templates** (no `.env` file). The Google Drive API key has
HTTP referrer restrictions in Google Cloud Console — when adding a new deployment domain,
update the allowed referrers: `*eltorobattalion.org/*`, `*.netlify.app/*`, `localhost/*`.

## Deployment Workflow

1. Create a `feature/` branch
2. Push → open a PR against `main`
3. Merge → GitHub Pages deploys `public/` to `eltorobattalion.org` automatically (~1 min)

To deploy without a PR, push directly to `main`.

## Replacing the Hero Video

When a new hero background video is provided (typically a `.mov` from iPhone/camera):

1. Place the source file anywhere (e.g. `public/assets/videos/new-hero.mov`)
2. Convert to web formats with ffmpeg:
```bash
# H.264 MP4 — Safari, Chrome (39MB target for a ~10s clip)
ffmpeg -i new-hero.mov -c:v libx264 -preset slow -crf 28 -movflags +faststart -an \
  public/assets/videos/hero-background.mp4

# VP9 WebM — Firefox, Android (target ~2Mbps = much smaller)
ffmpeg -i new-hero.mov -c:v libvpx-vp9 -b:v 2M -maxrate 3M -bufsize 6M \
  -deadline good -cpu-used 3 -an \
  public/assets/videos/hero-background.webm
```
3. Delete the source `.mov` (it's gitignored anyway: `public/assets/videos/*.mov`)
4. Run `python3 build.py` — the template already points to `hero-background.mp4/.webm`
5. Commit the two new video files

**Why these settings**: CRF 28 for H.264 balances quality and size for a background clip
(nobody scrutinises it). VP9 with a 2Mbps bitrate cap keeps the `.webm` under 10MB for
fast loads on Firefox/Android. `-an` strips audio (background video has no audio track).
ffmpeg must be installed: `brew install ffmpeg`.
